# Target website taxonomy

This is the target semantic structure for the Karzar public catalog. Maximum depth is four levels including the root family. Create only branches that have assigned products; do not expose empty categories publicly.

## Taxonomy principles

1. A category answers **what the product is or what operation it performs**.
2. Brand, size, diameter, ISO code, material, coating, interface, tolerance, handedness, number of flutes, machine compatibility, workpiece material, availability, and price are filters/attributes—not categories.
3. A product has one canonical primary website category. Existing supported secondary/cross-listing relationships may remain only when they do not create duplicate URLs or ambiguous breadcrumbs.
4. Maximum public depth is four.
5. Do not create categories by brand.
6. Reuse semantically correct existing category records/ids when safe. Preserve old public URLs with redirects when slugs change.
7. Do not guess ambiguous product classification. Record unresolved items in a focused CSV report while preserving their visibility under the nearest defensible existing/broad category.

## Hesabfa mapping semantics

Do not alter this taxonomy to match Hesabfa. Do not alter Hesabfa to match this taxonomy.

- Each website category has zero or one default `hesabfa_category_id` while not yet mapped.
- Once mapped and marked active, it has exactly one default Hesabfa category reference.
- Many website categories may reference the same Hesabfa category.
- A product may have an optional `hesabfa_category_id_override`.
- Product override takes precedence over the category default.
- Mapping is local metadata while integration is disabled and causes no remote write.
